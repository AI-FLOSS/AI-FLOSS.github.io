The AI Readiness Score measures how well a project is set up to accept AI-assisted contributions
safely. It has eight checks, one point each, and every check can be verified from public data about
the repository.

| Check | What counts | Guideline |
| --- | --- | --- |
| **AI usage policy** | An `AI_POLICY.md`, or a section about AI use in `CONTRIBUTING.md`, or an AI disclosure checkbox in the pull request template. Files in the owner's `.github` repository count too, since they apply to every repository. | [Disclosure](/guidelines/disclosure/) |
| **Agent guidance files** | `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`, Cursor, Windsurf or Cline rules. | [Prompting guidelines](/guidelines/prompting/) |
| **Tests run in CI** | A test suite, and a CI workflow that runs it on pull requests. | [Test-driven development](/guidelines/testing/) |
| **AI-assisted review** | An AI reviewer's config (such as CodeRabbit), an AI review action in CI, or an AI review bot active on recent pull requests. | [AI-assisted review](/guidelines/review/) |
| **Reproducible dev environment** | A devcontainer, Nix flake or shell, Dockerfile, devbox, pixi, mise or `.tool-versions` at the root, so an agent can build and test without guessing. | [Prompting guidelines](/guidelines/prompting/) |
| **Quality gates in CI** | A linter, formatter or type checker that runs on pull requests, or a pre-commit config. | [Test-driven development](/guidelines/testing/) |
| **Disclosure in practice** | At least one of the last 100 commits has an AI trailer such as `Assisted-by:`, or one of the last 30 pull requests has a ticked box in its AI section. | [Disclosure](/guidelines/disclosure/) |
| **Protected main branch** | A ruleset or branch protection that requires a pull request or passing checks before merging. | [AI-assisted review](/guidelines/review/) |

## What it does not measure

The score shows that the mechanisms exist, not how well they work. Test-driven development itself
cannot be seen from outside, so the score checks for the next best thing: tests that every pull
request must pass. A low score is not a judgement of a project's quality, only a list of things it
could add.

## Check your project

Run the [ai-readiness](https://github.com/x-tech-laboratories/ai-readiness) checker. It needs Node.js 20 or
later and a GitHub token, which it takes from `GITHUB_TOKEN` or from the GitHub CLI.

```sh
npx github:x-tech-laboratories/ai-readiness owner/repo
```

It prints the score and the file or activity that satisfied each check:

```text
owner/repo: 5/8
  ✓ AI usage policy  (AI_POLICY.md)
  ✓ Agent guidance files  (AGENTS.md)
  ✓ Tests run in CI  (tests/test_parser.py; CI: .github/workflows/test.yml)
  ✗ AI-assisted review
  ✓ Reproducible dev environment  (flake.nix)
  ✓ Quality gates in CI  (.github/workflows/lint.yml)
  ✗ Disclosure in practice
  ✗ Protected main branch
```

## Check it in CI

Add the GitHub Action to a workflow to see the score in every run's summary, or to fail the build
when it drops below a minimum:

```yaml
- uses: x-tech-laboratories/ai-readiness@v0
  with:
    min-score: 6
```

## Add a badge

Every project on [Awesome AI-Assisted Open Source](/awesome/) and every X-Tech Laboratories repository gets a
[shields.io](https://shields.io) badge that updates weekly. Replace `OWNER` and `REPO` with yours:

```md
[![AI readiness](https://img.shields.io/endpoint?url=https://x-tech-laboratories.github.io/badges/OWNER/REPO.json)](https://x-tech-laboratories.github.io/guidelines/readiness/)
```

For example, this website:
[![AI readiness](https://img.shields.io/endpoint?url=https://x-tech-laboratories.github.io/badges/x-tech-laboratories/x-tech-laboratories.github.io.json)](/guidelines/readiness/)

To get a badge for another project, [suggest it for Awesome AI-Assisted Open Source](/awesome/#suggest-a-project).

The checks are heuristics. If the checker gets your project wrong, please
[open an issue](https://github.com/x-tech-laboratories/ai-readiness/issues).
