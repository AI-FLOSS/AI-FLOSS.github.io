These pages collect the practices X-Tech Laboratories recommends, grouped by the four things we
stand for. They are drafts, written to be argued with: open an issue or pull request on
[GitHub](https://github.com/x-tech-laboratories/x-tech-laboratories.github.io) if you think
something is wrong or missing.

Each guideline stands on its own, so a project can adopt one without the others.

## Extensible, configurable, interoperable

- [Extensible and interoperable](/guidelines/extensibility): let one project serve many needs.

## Consolidate, don't fragment

- [Consolidation](/guidelines/consolidation): bring competing projects together without losing their users.

## Automation over toil

- [Automation](/guidelines/automation): let CI/CD carry the routine work.
- [Test-driven development](/guidelines/testing): make tests the contract every change must meet.
- [Readable code](/guidelines/readable-code): keep code simple enough for a person to take over.

## AI-assisted development

- [Prompting guidelines](/guidelines/prompting): tell AI agents how your project works.
- [Disclosure](/guidelines/disclosure): say how AI was involved in a change.
- [AI-assisted review](/guidelines/review): use AI to check code, not only to write it.
- [AI Readiness Score](/guidelines/readiness): check how ready a project is for AI-assisted development.
