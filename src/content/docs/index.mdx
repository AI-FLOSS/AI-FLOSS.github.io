## Why this community exists

<CardGrid>
  <Card title="AI learned from open source" icon="open-book">
    Today's coding models were trained largely on code that free software communities wrote and shared. That work deserves to benefit from what it made possible.
  </Card>
  <Card title="AI is not going away" icon="rocket">
    Companies already use AI to build and improve their products every day. If free software refuses the same tools on principle, it risks falling behind the proprietary alternatives it competes with.
  </Card>
  <Card title="Maintainers are stretched thin" icon="warning">
    Many important projects rest on a handful of volunteers, and ecosystems splinter into forks and half-finished rewrites. AI can take on the repetitive work of triage, tests, documentation and upkeep, so people can focus on direction and design.
  </Card>
  <Card title="Too much AI software is built alone and thrown away" icon="puzzle">
    Many free software communities turn away AI-assisted contributions, so people who build with AI start their own projects instead. Most of those end up with one user and no maintainer. AI-FLOSS gives them a shared home: one place where anyone can contribute, so effort goes into tools and apps everyone can use rather than a thousand one-off copies.
  </Card>
  <Card title="Disagreement doesn't have to mean a fork" icon="random">
    When people want different things from a project, the answer can be to make it extensible, pluggable, configurable and interoperable, so each person gets what they need from the same codebase.
  </Card>
  <Card title="Open source can lead" icon="star">
    With good tooling and good habits, community projects can move faster, stay maintained for longer, and stand up to their commercial counterparts on quality, not just on price.
  </Card>
</CardGrid>

## Principles

1. **People stay accountable.** Whoever submits a change owns it, however it was written.
2. **Be open about the tools.** Disclosure is normal and expected, never a mark against a contribution.
3. **Tests before trust.** Code is accepted because it is verified, not because of who or what wrote it.
4. **Readable by people.** All code, however it was written, stays simple and clear enough for a person to review and maintain without AI.
5. **Respect licences and upstreams.** AI-assisted work follows the same licensing and attribution rules as any other.
6. **Lighten the load on maintainers.** AI should reduce the work of reviewing contributions, not flood projects with low-effort ones.
7. **Build together, not alone.** Improve a shared project before starting a new one, and build it to last beyond its first user.
8. **Extend, don't fork.** Settle differences with plugins, settings and open formats, so one project can serve many needs.
9. **Share what works.** The guidelines, templates and tooling we build are free software too.
